# Medical Records RAG

A production-ready RAG (Retrieval-Augmented Generation) assistant for querying synthetic patient medical records using natural language.

---

## Problem Description

Clinicians and healthcare administrators spend significant time searching through patient records to answer questions like:
- "Which patients have both diabetes and hypertension?"
- "What medications is this patient currently taking?"
- "What were the last lab results for this patient?"

This project builds an LLM-powered assistant that answers natural language questions over synthetic patient records generated by [Synthea](https://github.com/synthetichealth/synthea), a realistic open-source patient data generator. The system retrieves relevant patient information using hybrid search (dense + sparse) and synthesizes accurate answers using GPT-4o-mini.

---

## Architecture
Synthea (125 synthetic patients, FHIR-compliant CSVs)
│
▼ Prefect pipeline
Raw CSVs → PostgreSQL (public schema)
│
▼ dbt (14 models, 62 tests)
staging.stg_* → marts.fct_patient_*
│
▼ LangChain chunker
68,298 text chunks (conditions, medications, observations, allergies, encounters)
│
▼ OpenAI text-embedding-3-small
Qdrant (vector store, 1536 dims, cosine similarity)
│
┌───┴───────────────────┐
Dense (Qdrant) Sparse (BM25)
└───┬───────────────────┘
│ LangChain EnsembleRetriever (50/50)
▼
LangChain ConversationalRetrievalChain
│
GPT-4o-mini
│
▼
FastAPI ──► Next.js + Tailwind CSS
│
├──► LangSmith (LLM tracing)
│
└──► PostgreSQL (query logs + feedback) ──► Grafana (8 panels)

## Quickstart

### 1. Clone the repository

```bash
git clone https://github.com/sargent-mg/medical-records-rag.git
cd medical-records-rag
```

### 2. Set up environment variables

```bash
cp .env.example .env
```

Edit `.env` and fill in:
- `OPENAI_API_KEY` — your OpenAI API key
- `LANGCHAIN_API_KEY` — your LangSmith API key

### 3. Generate synthetic patient data

Download Synthea and generate 125 patients:

```bash
mkdir -p tools data/raw
curl -L https://github.com/synthetichealth/synthea/releases/download/master-branch-latest/synthea-with-dependencies.jar -o tools/synthea.jar
java -jar tools/synthea.jar -p 125 --exporter.csv.export=true
mv output/csv/* data/raw/
rm -rf output/
```

### 4. Set up Python environment

```bash
uv sync
```

### 5. Run the ingestion pipeline

Make sure `.env` has `POSTGRES_HOST=localhost` and `QDRANT_HOST=localhost`, then start the infrastructure:

```bash
docker compose up postgres qdrant -d
```

Run the full pipeline (load CSVs → dbt → embed):

```bash
uv run python -m ingestion.pipeline
uv run python -m ingestion.embedder
```

### 6. Start the full stack

Update `.env` — set `POSTGRES_HOST=postgres` and `QDRANT_HOST=qdrant`, then:

```bash
docker compose up --build -d
```

### 7. Access the services

| Service | URL |
|---|---|
| Chat UI | http://localhost:3000 |
| API docs | http://localhost:8000/docs |
| Prefect UI | http://localhost:4200 |
| Grafana | http://localhost:3001 (admin/admin) |

### 8. Run evaluation

```bash
uv run python -m evaluation.ragas_eval
```

## LangSmith Tracing

Every chain invocation is automatically traced in LangSmith, including retrieval steps, prompt construction, and LLM calls. Set `LANGCHAIN_TRACING_V2=true` in `.env` to enable.
